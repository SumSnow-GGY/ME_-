# NTCdll → Linux `libNTCdll.so` 迁移计划

## 1. 项目目标

将原 Windows/MFC 版本：

```text
NTCdll.dll
```

独立迁移为 Linux 版本：

```text
libNTCdll.so
```

目标运行环境：

```text
Ubuntu Linux
x86_64
Qt6 / C++
CMake
GCC / G++
```

### 迁移原则

-   **不做 Windows/Linux 双平台兼容**
    
-   不保留 `_WIN32` 分支
    
-   不引入 MFC 兼容层
    
-   Windows 源代码仅作为**协议和业务行为参考**
    
-   Linux 版本重新设计底层网络实现
    
-   保持 NTC 网络协议兼容
    
-   保持 Client/Server 对外功能基本一致
    
-   优先保证稳定性和线程安全
    
-   最终用于 `HIDCamera_Qt6`

# 7. Windows IOCP → Linux epoll

这是整个迁移中最重要的架构变化。

原服务器：

```text
IOCP
 │
 ├── AcceptEx
 ├── WSARecv
 ├── WSASend
 ├── GetQueuedCompletionStatus
 └── Worker Thread
```

Linux：

```text
epoll
 │
 ├── listen socket
 ├── client socket
 ├── accept4()
 ├── recv()
 └── send()
```

推荐架构：

```text
                ┌──────────────┐
                │   epoll      │
                │ Event Loop   │
                └──────┬───────┘
                       │
         ┌─────────────┼─────────────┐
         ↓             ↓             ↓
      Listen FD      Client 1      Client 2
         │             │             │
      accept4()       recv()        recv()
                       │             │
                       ↓             ↓
                  CNTCContext   CNTCContext
```

不建议把 IOCP API 逐个模拟成 Linux API。

应该直接按照 Linux 网络模型重新实现。

# 8. NTC 网络协议

迁移过程中必须保持协议不变。

NTC 的基本消息格式：

```text
┌──────────────┬─────────────────────┐
│ 4 Byte Length│      Payload        │
└──────────────┴─────────────────────┘
```

也就是：

```text
[4-byte length][payload]
```

例如：

```text
04 00 00 00
```

表示后面有：

```text
4 Bytes Payload
```

# 9. 最大消息长度

原代码：

```cpp
#define MAX_BUFFER_SIZE 4096
```

Linux 保持：

```cpp
constexpr size_t MAX_BUFFER_SIZE = 4096;
```

要求：

```text
Payload <= 4096
```

超过：

```text
拒绝
```

不能因为 Linux 版本重构而改变协议限制。

# 10. NTCData ABI

原结构：

```cpp
typedef struct _NTCData
{
    UINT clientid;
    UINT msgtype;
    UINT msgSize;
    UINT msgCmd;
    char pData[512];
} NTCData;
```

Linux 不应该继续使用 `UINT`。

改为：

```cpp
struct NTCData
{
    uint32_t clientid;
    uint32_t msgtype;
    uint32_t msgSize;
    uint32_t msgCmd;
    char pData[512];
};
```

大小必须保持：

```text
4 × 4 + 512
= 528 Bytes
```

增加：

```cpp
static_assert(sizeof(NTCData) == 528);
```

这是为了保证 Windows/Linux 两端 ABI 一致。

# 14. CBuffer 数据流

例如 TCP 分两次收到：

```text

[Length][Payload的一部分]
```

```text
[Payload剩余部分]
```

必须能够拼接：

```text

 ↓
CBuffer
 ↓
判断是否完整
 ↓
完整消息
 ↓
callback
```

# 15. 必须支持 TCP 粘包

例如一次 recv 收到：

```text
[消息A][消息B][消息C]
```

CBuffer 必须循环解析：

```text
while(buffer >= header)
{
    获取 length

    判断完整消息

    如果完整：
        提取 payload
        callback()

    否则：
        等待下一次 recv
}
```

# 21. Client Partial Send

Linux `send()` 不保证一次发送全部数据。

例如：

```text

第一次：

剩余：

600
```

必须继续：

```text

send() → 300
```

直到：

```text

```

```text

EWOULDBLOCK
EINTR
```

# 42. `FindContextFromUserid()` 生命周期问题

原代码：

```text
获取 ConnectionList Lock
       ↓
找到 Context
       ↓
释放 Lock
       ↓
返回 Context*
```

这可能发生：

```text
Thread A:
找到 Context

Thread B:
关闭连接
释放 Context

Thread A:
继续使用 Context*
```

形成：

```text
Use After Free
```

Linux 版本需要重新设计生命周期管理。

# 58. 迁移的核心原则

整个项目最终只需要记住 **5 件事情**：

```text
① 不做双平台代码
② 不迁移 MFC
③ IOCP → epoll
④ 保持 NTC 协议不变
⑤ 每完成一个模块立即测试
```

其中最重要的是：

```text
Windows API 可以改变
Linux 网络架构可以改变
线程模型可以改变
内存管理可以改变

但是：

NTC 协议不能随意改变
```

因此我们的实际执行顺序是：

```text
NTCDefines
    ↓
CBuffer
    ↓
Client
    ↓
Server
    ↓
协议测试
    ↓
HIDCamera_Qt6
```

**下一步直接从 Step 1 开始，不要一次性把整个 NTCdll 全部改掉。** 每完成一个步骤就编译、测试，再进入下一步。
