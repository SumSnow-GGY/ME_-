# Linux迁移路线图

```text
Step 1: 准备阶段
├── 写跨平台 StdAfx.h（上面模块⑥的新版本）
├── 去掉 MFC 依赖：删掉 afxwin.h / afxext.h / afxole.h / afxcmn.h
├── 去掉 #pragma comment(lib,"ws2_32.lib")
├── 创建 CMakeLists.txt（linux 编译入口）
└── 验证：g++ 能编译通过（即使链接失败，先让编译过）

Step 2: 改 Client（难度小，先易后难）
├── Winsock → POSIX socket（模块②）
├── Sleep/nanosleep + _itoa/snprintf + wsprintf/snprintf
├── InterlockedIncrement/Decrement → __atomic_add_fetch/sub_fetch
├── HeapAlloc/Free → malloc/free
├── PostMessage → callback（模块⑤）
├── WSAStartup/WSACleanup → 空函数
├── WaitForSingleObject(pthread_join) + CreateThread(pthread_create)
├── EnterCriticalSection(pthread_mutex_lock)
└── 验证：Client 单独能编译，能连 Linux 的 nc 测试服务

Step 3: 改 Server 的线程 + 同步
├── CreateThread → pthread_create
├── CriticalSection → pthread_mutex
├── WaitForMultipleObjects → signalfd + pipe 组合
├── Event → Mutex+Cond 包装（上面模块③的代码）
├── InterlockedIncrement → __atomic
└── 验证：多线程能正常启动和停止

Step 4: 改 Server 的 IOCP → epoll（最核心）
├── CreateIoCompletionPort → epoll_create1
├── 删掉 AcceptEx 预投递逻辑
├── 删掉 PostRecv / PostSend
├── HandleIO 重写：EPOLLET + recv/send 手动循环
├── OnReadCompleted 保留（业务逻辑不变！）
├── 对象池保留（AllocateContext / ReleaseContext 逻辑不变）
└── 验证：Server 能启动，Client 能连接

Step 5: 收尾
├── 全部 PostMessage → callback
├── HWND 参数清理
├── DllMain → __attribute__ constructor
├── VirtualAlloc → mmap / realloc
├── 删掉 resource.h / vld.h
└── 端到端测试：Console → Server → Camera 完整通信
```
