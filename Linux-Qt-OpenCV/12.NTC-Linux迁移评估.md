# stdafx.h 文件
**Visual C++ / MFC 工程预编译头文件**

```cpp 
源码
#include <afxwin.h>
#include <afxext.h>
#include <afxole.h>
#include <afxodlgs.h>
#include <afxdisp.h>
#include <afxdb.h>
#include <afxdao.h>
#include <afxdtctl.h>
#include <afxcmn.h>
#include <winsock2.h>
#pragma comment(lib,"ws2_32.lib")
```
-   引入 MFC 核心组件
-   引入 MFC 扩展组件
-   引入 OLE / COM 支持
-   引入数据库支持
-   引入 Windows Common Controls
-   引入 Winsock 网络通信
-   设置部分 Windows 编译环境
-   自动链接 Windows 网络库

| 原始内容 | Windows 作用 | Linux 是否存在 | Linux 处理方式 | 建议 |
 |---|---|---|---|---|
  | `afxwin.h` | MFC 核心组件 | 否 | 使用 Qt 替代 | 删除 | | `afxext.h` | MFC 扩展组件 | 否 | 使用 Qt 替代 | 删除 | | `afxole.h` | MFC OLE 支持 | 否 | 根据实际功能使用 Qt/DBus 等替代 | 检查后处理 | 
  | `afxodlgs.h` | OLE 对话框 | 否 | 使用 Qt Widgets | 检查后处理 | 
  | `afxdisp.h` | MFC Automation / COM | 否 | 根据实际功能重新实现 | 检查后处理 | | `afxdb.h` | MFC ODBC 数据库 | 否 | 使用 Qt SQL / ODBC | 检查后处理 | 
  | `afxdao.h` | MFC DAO 数据库 | 否 | 使用 Qt SQL 或其他数据库接口 | 检查后处理 | | `afxdtctl.h` | IE4 Common Controls | 否 | 使用 Qt Widgets | 通常删除 | 
  | `afxcmn.h` | Windows Common Controls | 否 | 使用 Qt Widgets | 删除 | | `winsock2.h` | Windows Socket | 否 | 使用 POSIX Socket | 替换 | 
  | `#pragma comment(lib,"ws2_32.lib")` | MSVC 自动链接 Winsock | 否 | Linux 不需要 | 删除 | 
  | `VC_EXTRALEAN` | 减少 MFC 头文件包含 | 否 | Linux 无对应机制 | 删除 | 
  | `_WIN32_WINNT 0x0502` | 指定 Windows API 版本 | 否 | Linux 不需要 | 删除或仅 Windows 保留 |
  | `#pragma once` | 防止头文件重复包含 | 是 | GCC 支持 | 保留 | 
  | `#if !defined(...)` | Header Guard | 是 | GCC 支持 | 保留 | | `#endif` | 条件编译结束 | 是 | GCC 支持 | 保留 |

## 真正目标： 
让 NTCdll 核心代码脱离 MFC / Windows API， 最终使用 GCC 编译生成 Linux `.so`。

## NTC.cpp

核心代码只有：
```cpp
static AFX_EXTENSION_MODULE NTCDLL = { NULL, NULL };
```

```cpp
if (dwReason == DLL_PROCESS_ATTACH)
{
    if (!AfxInitExtensionModule(NTCDLL, hInstance))
        return 0;
    new CDynLinkLibrary(NTCDLL);
}
```
Linux 版本不需要把 MFC DLL 初始化机制“翻译”为 Linux 代码，而是直接去掉这一层。

## NTCBuffer .h/.cpp文件
NTCBuffer.h/.cpp Linux 移植修改总结
================================================================================

一、Windows 类型/API 替换
--------------------------------------------------------------------------------
| Windows 类型/API       | Linux 建议实现          | 优先级 | 注意事项             |
|------------------------|-------------------------|--------|----------------------|
| PBYTE                  | uint8_t*                | P0     | 引入 <cstdint>       |
| UINT                   | size_t                  | P0     | 用于内存长度         |
| UINT                   | uint32_t                | P0     | 用于协议字段         |
| BOOL                   | bool                    | P0     | Linux C++ 推荐       |
| NULL                   | nullptr                 | P0     | C++11                |
| VirtualAlloc()         | malloc()                | P0     | 必须检查返回值       |
| VirtualFree()          | free()                  | P0     | 与 malloc 配套       |
| CopyMemory()           | memcpy()                | P0     | 引入 <cstring>       |
| MoveMemory()           | memmove()               | P0     | 不可随意改成 memcpy  |
| CString                | std::string             | P0     | 去除 MFC 依赖        |
| CFile                  | std::ofstream / FILE*   | P0     | 去除 MFC 依赖        |
--------------------------------------------------------------------------------


二、CBuffer 成员变量
--------------------------------------------------------------------------------
| 成员变量       | 当前类型 | 实际含义             | Linux 建议类型 |
|----------------|----------|----------------------|----------------|
| m_pBase        | PBYTE    | Buffer 起始地址      | uint8_t*       |
| m_pPtr         | PBYTE    | 有效数据末尾位置     | uint8_t*       |
| m_nSize        | UINT     | 已分配内存容量       | size_t         |
--------------------------------------------------------------------------------


三、各函数修改重点
--------------------------------------------------------------------------------
| 函数                    | 作用                 | Linux 移植重点       |
|-------------------------|----------------------|----------------------|
| CBuffer()               | 初始化 Buffer        | NULL → nullptr       |
| ~CBuffer()              | 释放内存             | VirtualFree → free   |
| Write()                 | 末尾追加数据         | 检查扩容是否成功     |
| Insert()                | 开头插入数据         | memmove + 有效长度   |
| Read()                  | 读取并删除数据       | 注意移动数据范围     |
| Delete()                | 删除前面的数据       | 注意移动数据范围     |
| GetMemSize()            | 获取容量             | 保持原逻辑           |
| GetBufferLen()          | 获取有效长度         | 指针差值             |
| ReAllocateBuffer()      | 扩容                 | 检查 malloc 失败     |
| DeAllocateBuffer()      | 重新分配             | 实际不会主动缩容     |
| ClearBuffer()           | 清空数据             | 通常保留已分配内存   |
| Scan()                  | 搜索字符串           | 确认是否支持二进制   |
| Copy()                  | Buffer 复制          | 增加自拷贝保护       |
| GetBuffer()             | 获取内部指针         | 注意指针失效问题     |
| FileWrite()             | 写入文件             | CFile → 标准 C++    |
| Insert(CString&)        | 插入字符串           | CString → std::string|
| Write(CString&)         | 追加字符串           | 当前代码已经注释     |
--------------------------------------------------------------------------------


四、需要重点修复的问题
--------------------------------------------------------------------------------
| 问题                              | 严重程度 | 建议                 |
|-----------------------------------|----------|----------------------|
| VirtualAlloc 无法在 Linux 使用    | P0       | 必须替换             |
| VirtualFree 无法在 Linux 使用     | P0       | 必须替换             |
| CopyMemory 无法在 Linux 使用      | P0       | 替换为 memcpy        |
| MoveMemory 无法在 Linux 使用      | P0       | 替换为 memmove       |
| CString 依赖 MFC                  | P0       | 改为 std::string     |
| CFile 依赖 MFC                    | P0       | 改为标准文件接口     |
| malloc 失败没有检查               | P0       | 必须增加 nullptr 检查|
| Insert 移动整个 Buffer 容量       | P1       | 改为移动有效数据     |
| Read 移动整个 Buffer 容量         | P1       | 改为移动有效数据     |
| Delete 移动整个 Buffer 容量       | P1       | 改为移动有效数据     |
| Copy 没有自拷贝保护               | P1       | 增加 this 判断       |
| Scan 使用 strstr                  | P1       | 确认协议后决定       |
| GetBuffer 没有边界检查            | P2       | 第一阶段暂不修改     |
| GetBuffer 返回裸指针              | P2       | 注意生命周期         |
| 使用 std::vector 全面重构         | P3       | 第一阶段暂不进行     |
--------------------------------------------------------------------------------


五、Insert/Read/Delete 的重要问题
--------------------------------------------------------------------------------

原代码使用：

MoveMemory(..., GetMemSize() - nSize);

这里 GetMemSize() 是：

    Buffer 总容量

而不是：

    Buffer 有效数据长度

例如：

    Buffer 容量 = 4096
    有效数据   = 100
    删除数据   = 10

原代码可能移动：

    4096 - 10 = 4086 bytes

实际上只需要移动：

    100 - 10 = 90 bytes

因此 Linux 版本建议改为：

    memmove(
        m_pBase,
        m_pBase + nSize,
        GetBufferLen() - nSize
    );

Insert() 同理，只移动有效数据。


六、ReAllocateBuffer() 的内存安全问题
--------------------------------------------------------------------------------

当前逻辑：

    VirtualAlloc()
        ↓
    CopyMemory()
        ↓
    VirtualFree()
        ↓
    更新指针

Linux 版本建议：

    malloc()
        ↓
    检查是否 nullptr
        ↓
    memcpy()
        ↓
    free(旧内存)
        ↓
    更新 m_pBase
        ↓
    更新 m_pPtr
        ↓
    更新 m_nSize

绝对不要：

    先 free 旧内存
        ↓
    再 malloc 新内存

否则 malloc 失败时会导致原 Buffer 数据丢失。


七、Scan() 注意事项
--------------------------------------------------------------------------------

当前实现：

    strstr()
    strlen()

因此 Scan() 实际上是：

    字符串搜索

而不是：

    二进制 Buffer 搜索

如果 NTC 协议中存在：

    00

这样的二进制数据，那么 strstr() 会提前结束。

因此：

    Scan()

暂时不要直接修改。

需要等：

    NTCClient.cpp
    NTCServer.cpp

分析完成以后，再确认它到底搜索：

    字符串分隔符
    消息头
    二进制数据
    其他协议标志


八、GetBuffer() 注意事项
--------------------------------------------------------------------------------

当前：

    GetBuffer()

直接返回：

    m_pBase + nPos

因此返回的是内部裸指针。

例如：

    PBYTE p = buffer.GetBuffer();

然后：

    buffer.Write(...);

如果 Write() 触发 ReAllocateBuffer()：

    旧内存
       ↓
    被释放
       ↓
    p 成为悬空指针

因此后续分析 NTCClient/NTCServer 时，需要重点检查：

    GetBuffer()
        ↓
    保存指针
        ↓
    Buffer 重新分配
        ↓
    是否继续使用旧指针


九、第一阶段移植原则
--------------------------------------------------------------------------------

第一阶段：

    Windows API 替换
            +
    MFC 类型替换
            +
    明显内存问题修复
            +
    保持原有协议行为
            +
    保持 CBuffer 接口基本不变

暂时不要：

    大规模重构 CBuffer
    直接改成 std::vector
    修改 NTC 协议结构
    修改 Scan() 返回值语义
    修改 Read/Delete 行为
    修改 NTCData 数据布局


十、最终目标
--------------------------------------------------------------------------------

Windows：

    NTCdll
       |
       +-- CBuffer
       |     +-- VirtualAlloc
       |     +-- VirtualFree
       |     +-- CopyMemory
       |     +-- MoveMemory
       |     +-- CString
       |     +-- CFile
       |
       +-- NTCClient
       |
       +-- NTCServer


Linux：

    libNTCdll.so
       |
       +-- CBuffer
       |     +-- malloc/free
       |     +-- memcpy/memmove
       |     +-- std::string
       |     +-- std::ofstream
       |
       +-- NTCClient
       |
       +-- NTCServer
核心原则：
    平台替换优先
    行为兼容优先
    协议逻辑保持不变
    内存安全优先
    大规模重构放到后面
