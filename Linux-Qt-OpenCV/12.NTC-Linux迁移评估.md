# stdafx.h 文件
**Visual C++ / MFC 工程预编译头文件**

```cpp 
源码
#include <afxwin.h>
#include <afxext.h>
#include <afxole.h>
#include <afxodlgs.h>
#include <afxdisp.h>
#include <afxdb.h>
#include <afxdao.h>
#include <afxdtctl.h>
#include <afxcmn.h>
#include <winsock2.h>
#pragma comment(lib,"ws2_32.lib")
```
-   引入 MFC 核心组件
-   引入 MFC 扩展组件
-   引入 OLE / COM 支持
-   引入数据库支持
-   引入 Windows Common Controls
-   引入 Winsock 网络通信
-   设置部分 Windows 编译环境
-   自动链接 Windows 网络库

| 原始内容 | Windows 作用 | Linux 是否存在 | Linux 处理方式 | 建议 |
 |---|---|---|---|---|
  | `afxwin.h` | MFC 核心组件 | 否 | 使用 Qt 替代 | 删除 | | `afxext.h` | MFC 扩展组件 | 否 | 使用 Qt 替代 | 删除 | | `afxole.h` | MFC OLE 支持 | 否 | 根据实际功能使用 Qt/DBus 等替代 | 检查后处理 | 
  | `afxodlgs.h` | OLE 对话框 | 否 | 使用 Qt Widgets | 检查后处理 | 
  | `afxdisp.h` | MFC Automation / COM | 否 | 根据实际功能重新实现 | 检查后处理 | | `afxdb.h` | MFC ODBC 数据库 | 否 | 使用 Qt SQL / ODBC | 检查后处理 | 
  | `afxdao.h` | MFC DAO 数据库 | 否 | 使用 Qt SQL 或其他数据库接口 | 检查后处理 | | `afxdtctl.h` | IE4 Common Controls | 否 | 使用 Qt Widgets | 通常删除 | 
  | `afxcmn.h` | Windows Common Controls | 否 | 使用 Qt Widgets | 删除 | | `winsock2.h` | Windows Socket | 否 | 使用 POSIX Socket | 替换 | 
  | `#pragma comment(lib,"ws2_32.lib")` | MSVC 自动链接 Winsock | 否 | Linux 不需要 | 删除 | 
  | `VC_EXTRALEAN` | 减少 MFC 头文件包含 | 否 | Linux 无对应机制 | 删除 | 
  | `_WIN32_WINNT 0x0502` | 指定 Windows API 版本 | 否 | Linux 不需要 | 删除或仅 Windows 保留 |
  | `#pragma once` | 防止头文件重复包含 | 是 | GCC 支持 | 保留 | 
  | `#if !defined(...)` | Header Guard | 是 | GCC 支持 | 保留 | | `#endif` | 条件编译结束 | 是 | GCC 支持 | 保留 |

## 真正目标： 
让 NTCdll 核心代码脱离 MFC / Windows API， 最终使用 GCC 编译生成 Linux `.so`。

五、Insert/Read/Delete 的重要问题
--------------------------------------------------------------------------------

原代码使用：

MoveMemory(..., GetMemSize() - nSize);

这里 GetMemSize() 是：

    Buffer 总容量

而不是：

    Buffer 有效数据长度

例如：

    Buffer 容量 = 4096
    有效数据   = 100
    删除数据   = 10

原代码可能移动：

    4096 - 10 = 4086 bytes

实际上只需要移动：

    100 - 10 = 90 bytes

因此 Linux 版本建议改为：

    memmove(
        m_pBase,
        m_pBase + nSize,
        GetBufferLen() - nSize
    );

Insert() 同理，只移动有效数据。


六、ReAllocateBuffer() 的内存安全问题
--------------------------------------------------------------------------------

当前逻辑：

    VirtualAlloc()
        ↓
    CopyMemory()
        ↓
    VirtualFree()
        ↓
    更新指针

Linux 版本建议：

    malloc()
        ↓
    检查是否 nullptr
        ↓
    memcpy()
        ↓
    free(旧内存)
        ↓
    更新 m_pBase
        ↓
    更新 m_pPtr
        ↓
    更新 m_nSize

绝对不要：

    先 free 旧内存
        ↓
    再 malloc 新内存

否则 malloc 失败时会导致原 Buffer 数据丢失。


七、Scan() 注意事项
--------------------------------------------------------------------------------

当前实现：

    strstr()
    strlen()

因此 Scan() 实际上是：

    字符串搜索

而不是：

    二进制 Buffer 搜索

如果 NTC 协议中存在：

    00

这样的二进制数据，那么 strstr() 会提前结束。

因此：

    Scan()

暂时不要直接修改。

需要等：

    NTCClient.cpp
    NTCServer.cpp

分析完成以后，再确认它到底搜索：

    字符串分隔符
    消息头
    二进制数据
    其他协议标志


八、GetBuffer() 注意事项
--------------------------------------------------------------------------------

当前：

    GetBuffer()

直接返回：

    m_pBase + nPos

因此返回的是内部裸指针。

例如：

    PBYTE p = buffer.GetBuffer();

然后：

    buffer.Write(...);

如果 Write() 触发 ReAllocateBuffer()：

    旧内存
       ↓
    被释放
       ↓
    p 成为悬空指针

因此后续分析 NTCClient/NTCServer 时，需要重点检查：

    GetBuffer()
        ↓
    保存指针
        ↓
    Buffer 重新分配
        ↓
    是否继续使用旧指针

          ↓

        CreateConnectedSocket();

                → OnRead()

                → OnWrite()/连接完成

六、OnRead() 修改
--------------------------------------------------------------------------------

Windows：

    ioctlsocket(
        m_Socket,
        FIONREAD,
        &dwSize
    );


Linux 可以使用：

    ioctl(
        m_Socket,
        FIONREAD,
        &dwSize
    );


但是更推荐后续直接：

    recv()

持续读取，然后交给：

    m_recvBuff

处理 TCP 粘包/拆包。


核心协议必须保持：

    [4 Byte 数据长度][Payload]


接收流程：

    recv()
       ↓
    m_recvBuff.Write()
       ↓
    读取前4字节
       ↓
    得到 nSize
       ↓
    判断完整数据
       ↓
    删除4字节Header
       ↓
    读取Payload
       ↓
    callback()


七、OnRead() 协议安全修改
--------------------------------------------------------------------------------

当前：

    int nSize;

    CopyMemory(
        &nSize,
        m_recvBuff.GetBuffer(),
        sizeof(int)
    );


Linux 第一版建议增加：

    nSize > 0
    nSize <= MAX_BUFFER_SIZE


即：

    nSize <= 0
        → 异常数据

    nSize > MAX_BUFFER_SIZE
        → 异常数据

    0 < nSize <= MAX_BUFFER_SIZE
        → 正常处理


原因：

    防止异常网络数据导致：

    new BYTE[nSize + 1]

    分配异常大小内存。


八、OnRead() callback
--------------------------------------------------------------------------------

Windows：

    m_ClientCallback(
        m_recvBuffer->buff,
        m_recvBuffer->nLen
    );


Linux：

    保留 callback 机制。


建议：

    if (m_ClientCallback != nullptr)
    {
        m_ClientCallback(
            m_recvBuffer->buff,
            m_recvBuffer->nLen
        );
    }


必须增加 nullptr 检查。

否则：

    没有注册 callback
        ↓
    收到数据
        ↓
    调用 NULL 函数指针
        ↓
    崩溃

十一、DoAsyncSendBuff() 修改
--------------------------------------------------------------------------------

当前：

    send()
        ↓
    SOCKET_ERROR
        ↓
    WSAEWOULDBLOCK
        ↓
    Sleep(100)


Linux：

    send()
        ↓
    返回 -1
        ↓
    errno == EAGAIN/EWOULDBLOCK
        ↓
    poll(POLLOUT)


第一版也可以暂时保持：

    sleep(100ms)

但更推荐：

    poll()

等待 Socket 可写。


必须保留：

    Partial Send


例如：

    总数据 = 532 bytes

    第一次 send = 200 bytes

    剩余 = 332 bytes

    第二次继续发送


所以：

    m_nBytesSent

和：

    m_sendBuff.Delete(nBytes)

的逻辑不能删除。


十二、ntcSendMessageToServer() 修改
--------------------------------------------------------------------------------

当前协议：

    nSize = uLen

    m_sendBuff.Write(
        &nSize,
        sizeof(nSize)
    );

    m_sendBuff.Write(
        pSendData,
        nSize
    );


必须保持：

    [4 Byte Length]
    +
    [Payload]


不要改成：

    直接发送 Payload


否则 Server 无法按照现有协议解析。


十三、ntcSendMessageToServer() 已发现 Bug
--------------------------------------------------------------------------------

当前：

    pBuffer = AllocateBuffer(uLen);

    if(pBuffer != NULL)
    {
        ...
    }

    ReleaseBuffer(pBuffer);


如果：

    uLen > MAX_BUFFER_SIZE

则：

    AllocateBuffer()
        ↓
    NULL

然后：

    ReleaseBuffer(NULL)

可能导致崩溃。


Linux 必须修改为：

    if (pBuffer != nullptr)
    {
        ...
        ReleaseBuffer(pBuffer);
    }


这是明确需要修复的 Bug。


十四、CNTCBufferClient 内存池
--------------------------------------------------------------------------------

Windows：

    HeapAlloc()
        ↓
    CNTCBufferClient
        +
    MAX_BUFFER_SIZE

Linux：

    malloc()

内存结构保持：

    +--------------------------------+
    | CNTCBufferClient               |
    +--------------------------------+
    | MAX_BUFFER_SIZE bytes          |
    |                                |
    | buff                           |
    +--------------------------------+


不建议第一阶段改成：

    std::vector

或者：

    std::shared_ptr


第一阶段保持原有内存布局，减少协议/行为变化。


十五、AllocateBuffer() 修改
--------------------------------------------------------------------------------

Windows：

    GetProcessHeap()
    HeapAlloc()
    HEAP_ZERO_MEMORY


Linux：

    malloc()
    memset()


建议：

    void* p = malloc(
        sizeof(CNTCBufferClient)
        + MAX_BUFFER_SIZE
    );

    if (p == nullptr)
        return nullptr;

    memset(
        p,
        0,
        sizeof(CNTCBufferClient)
        + MAX_BUFFER_SIZE
    );


然后：

    pBuffer->buff =
        reinterpret_cast<char*>(pBuffer + 1);


十六、ReleaseBuffer() 修改
--------------------------------------------------------------------------------

Windows：

    HeapFree()


Linux：

    free()


需要增加：

    if (pBuffer == nullptr)
        return;


同时建议修正：

    if (m_nFreeBufferCount <= m_nMaxFreeBuffers)


为：

    if (m_nFreeBufferCount < m_nMaxFreeBuffers)


如果设计目标是最多缓存 200 个 Buffer。


十七、FreeBuffers() 修改
--------------------------------------------------------------------------------

Windows：

    HeapFree(
        GetProcessHeap(),
        ...
    );


Linux：

    free(pFreeBuffer);


需要保持：

    链表遍历
        ↓
    一个一个释放
        ↓
    m_pFreeBufferList = nullptr
        ↓
    m_nFreeBufferCount = 0


十八、临界区修改
--------------------------------------------------------------------------------

Windows：

    CRITICAL_SECTION


Linux：

    std::mutex


原：

    EnterCriticalSection(
        &m_criticalSection
    );


Linux：

    std::lock_guard<std::mutex>
        lock(m_criticalSection);


FreeBufferList 同理：

    m_FreeBufferListLock


建议使用 RAII：

    std::lock_guard<std::mutex>


不要手动：

    lock()
    ...
    unlock()


这样可以避免异常路径忘记解锁。


十九、ntcClientCloseConnection() 修改
--------------------------------------------------------------------------------

Windows：

    SetEvent()
        ↓
    WaitForSingleObject()
        ↓
    closesocket()
        ↓
    WSACleanup()
        ↓
    FreeBuffers()
        ↓
    WSACloseEvent()
        ↓
    CloseHandle()


Linux：

    m_stop = true
        ↓
    唤醒/结束 poll()
        ↓
    thread.join()
        ↓
    close(m_Socket)
        ↓
    FreeBuffers()


不需要：

    WSACleanup()
    WSACloseEvent()
    CloseHandle()


二十、线程退出设计
--------------------------------------------------------------------------------

建议：

    std::atomic<bool> m_stop;


连接线程：

    while (!m_stop)
    {
        ...
    }


关闭：

    m_stop = true;

    if (m_thread.joinable())
        m_thread.join();


注意：

    不要在线程还运行时
    直接 free Client 内部资源。


否则可能出现：

    主线程 FreeBuffers()
            +
    SocketThreadProc()
            ↓
        同时访问
            ↓
        内存崩溃


二十一、HWND / PostMessage 最终处理
--------------------------------------------------------------------------------

Windows：

    HWND
       ↓
    PostMessage()
       ↓
    WM_NTCMESSAGE


Linux：

    删除 HWND


统一：

    callback


最终：

    libNTCdll.so
          ↓
    m_ClientCallback()
          ↓
    HIDCamera_Qt6
          ↓
    Qt Signal / Slot


这是 Linux 版本推荐的架构。


二十二、Message Map 修改
--------------------------------------------------------------------------------

Windows：

    CNetworkMessageMap

    ProcessNetworkMessage()

    FD_READ
    FD_CLOSE
    FD_CONNECT
    FD_ACCEPT


Linux：

    不需要保留 MFC Message Map。

    poll()
       ↓
    switch(revents)

    OnRead()

    OnConnect()
    OnClose()

    确认它为什么存在。

核心结论
================================================================================

NTCClient Linux 移植最重要的不是 Socket 本身。

真正需要处理的核心有 6 个：

    1. Windows Socket Event
       WSAEventSelect
       WSAWaitForMultipleEvents
       WSAEnumNetworkEvents
       ↓
       poll()

    2. Windows Thread
       CreateThread
       HANDLE
       ↓
       std::thread

    3. Windows Synchronization
       CRITICAL_SECTION
       ↓
       std::mutex

    4. Windows Memory
       HeapAlloc / HeapFree
       ↓
       malloc / free

    5. Windows GUI Notification
       HWND / PostMessage
       ↓
       callback

    6. Windows Socket API
       WSAxxx / closesocket
       ↓
       POSIX socket / close / errno
