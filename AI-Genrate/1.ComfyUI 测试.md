


# ComfyUI 安装与 Stable Diffusion XL 使用笔记

> 环境：Ubuntu Linux  
> GPU：NVIDIA RTX 5060  
> CUDA：12.x  
> 模型：Stable Diffusion XL Base 1.0  
> UI：ComfyUI
> 
> 本笔记记录一次从安装 ComfyUI 到成功运行 SDXL 工作流的完整过程。

----------

# 1. ComfyUI 简介

ComfyUI 是一个基于**节点（Node）工作流**的 Stable Diffusion 图像生成界面。

与传统 WebUI 不同，ComfyUI 不直接把所有参数集中在一个页面，而是通过节点连接形成完整的生成流程。

典型的 Stable Diffusion 工作流：

```text
加载模型
   ↓
文本提示词
   ↓
采样
   ↓
Latent
   ↓
VAE 解码
   ↓
保存图片

```

----------

可以直接从 GitHub 获取：

```bash
git clone https://github.com/comfyanonymous/ComfyUI.git

```


```bash
conda activate comfyui
```

```bash
python --version
```

# 9. 添加基础工作流

本次使用的核心节点：

```text
Load Checkpoint
CLIP Text Encode（正面）
CLIP Text Encode（负面）
Empty Latent Image
KSampler
VAE Decode
Save Image

```

完整流程：

```text
                    ┌──→ CLIP Text Encode（正面） ──┐
                    │                               │
Load Checkpoint ────┤                               ↓
                    │                           KSampler
                    │                               ↑
                    └──→ CLIP Text Encode（负面） ──┘
                                                    ↑
Empty Latent Image ─────────────────────────────────┘
                                                    │
                                                    ↓
                                                VAE Decode
                                                    │
                                                    ↓
                                                Save Image

```

----------

# 10. Load Checkpoint

添加：

```text
Load Checkpoint

```

这个节点负责加载 Stable Diffusion 模型。

它通常会提供三个主要输出：

```text
MODEL
CLIP
VAE

```

分别对应：

```text
MODEL → KSampler
CLIP  → CLIP Text Encode
VAE   → VAE Decode

```

----------

# 11. CLIP Text Encode

需要添加两个：

```text
CLIP Text Encode

```

分别作为：

```text
正面提示词
负面提示词

```

## 11.1 正面提示词

例如：

```text
a cat wearing a spacesuit, swimming in a swimming pool,
high quality, detailed, cinematic lighting

```

连接：

```text
Load Checkpoint
       │
      CLIP
       │
       ↓
CLIP Text Encode
       │
   CONDITIONING
       ↓
    KSampler

```

----------

## 11.2 负面提示词

例如：

```text
low quality, blurry, distorted, deformed,
bad anatomy, extra limbs

```

同样使用：

```text
Load Checkpoint
       │
      CLIP
       │
       ↓
CLIP Text Encode
       │
   CONDITIONING
       ↓
    KSampler

```

但是需要连接到 KSampler 的：

```text
negative

```

输入。

----------

# 12. Empty Latent Image

添加：

```text
Empty Latent Image

```

这个节点负责生成初始 Latent。

例如 SDXL 可以使用：

```text
Width: 1024
Height: 1024
Batch Size: 1

```

输出：

```text
LATENT

```

连接：

```text
Empty Latent Image
        │
      LATENT
        ↓
     KSampler

```

----------

# 13. KSampler

KSampler 是整个生成流程的核心。

它负责：

```text
Noise
+
Model
+
Positive Conditioning
+
Negative Conditioning
+
Sampling Parameters

```

最终生成：

```text
LATENT

```

主要参数：

```text
seed
steps
cfg
sampler_name
scheduler
denoise

```

----------

# 14. Seed

例如：

```text
Seed: 123456789

```

Seed 决定随机噪声。

如果：

```text
模型相同
提示词相同
参数相同
Seed 相同

```

通常可以得到一致的结果。

因此在测试不同参数时，建议：

> **固定 Seed，只修改一个参数。**

这样才能比较参数变化带来的实际影响。

----------

# 15. Steps

例如：

```text
Steps: 20

```

Steps 表示采样迭代次数。

一般来说：

```text
Steps ↑
    ↓
生成时间 ↑

```

但：

```text
Steps ↑

```

并不意味着：

```text
图片质量无限 ↑

```

达到一定范围以后，继续增加 Steps 的收益会降低。

SDXL 初步测试可以使用：

```text
20 ~ 30

```

----------

# 16. CFG

CFG 用于控制提示词对生成结果的影响。

例如：

```text
CFG = 7

```

一般可以先从：

```text
5 ~ 8

```

进行测试。

CFG 太高可能出现：

```text
画面过度强调提示词
颜色/结构异常
细节变得不自然

```

----------

# 17. Sampler 与 Scheduler

这是本次测试过程中一个比较重要的地方。

KSampler 中有：

```text
Sampler
Scheduler

```

两个参数。

它们不是同一个东西。

----------

## 17.1 Sampler

Sampler 可以理解为：

> **具体采用什么算法从噪声逐步生成图像。**

例如：

```text
euler
euler_ancestral
heun
dpmpp_2m
dpmpp_2m_sde
dpmpp_2m_sde_gpu

```

不同 Sampler 会影响：

```text
细节
构图
锐度
稳定性
生成风格

```

----------

## 17.2 Scheduler

Scheduler 可以理解为：

> **如何安排每一步去噪过程中的噪声强度。**

常见：

```text
normal
karras
exponential
sgm_uniform
simple

```

所以：

```text
Sampler
+
Scheduler

```

共同决定实际的采样过程。

----------

# 18. 为什么更换 Sampler / Scheduler 后结果差异很大？

例如固定：

```text
Model
Prompt
Seed
Steps
CFG

```

只改变：

```text
Sampler

```

或者：

```text
Scheduler

```

最终图片仍然可能产生明显区别。

因此：

> **Sampler 和 Scheduler 都属于影响最终图像效果的重要参数。**

进行实验时建议一次只修改一个。

----------

# 19. VAE Decode

KSampler 输出的是：

```text
LATENT

```

这还不是普通图片。

需要经过：

```text
VAE Decode

```

将 Latent 转换成：

```text
IMAGE

```

连接：

```text
KSampler
   │
 LATENT
   ↓
VAE Decode
   │
 IMAGE
   ↓
Save Image

```

VAE 输入：

```text
VAE

```

来自：

```text
Load Checkpoint

```

----------

# 20. Save Image

最后添加：

```text
Save Image

```

连接：

```text
VAE Decode
      │
    IMAGE
      ↓
  Save Image

```

ComfyUI 会自动保存生成的图片。

----------

# 21. 完整节点连接

最终完整连接关系：

```text
                 ┌──────────────────────────────┐
                 │                              │
                 │        Load Checkpoint       │
                 │                              │
                 └──────────────────────────────┘
                    │        │             │
                    │        │             │
                  MODEL     CLIP           VAE
                    │        │             │
                    │        │             │
                    │    ┌───┴────┐        │
                    │    │        │        │
                    │    ↓        ↓        │
                    │ Positive  Negative    │
                    │ CLIP      CLIP        │
                    │ Encode    Encode      │
                    │    │        │         │
                    │    │        │         │
                    ↓    ↓        ↓         │
                 ┌─────────────────────┐    │
                 │      KSampler       │    │
                 └─────────────────────┘    │
                           ↑                │
                           │                │
                    Empty Latent Image      │
                           │                │
                           └────────────────┘
                           │
                           ↓
                       LATENT
                           │
                           ↓
                      VAE Decode
                           ↑
                           │
                          VAE
                           │
                           ↓
                       Save Image

```

更准确地说，关键连接如下：

```text
Load Checkpoint.MODEL
        ↓
KSampler.model


Load Checkpoint.CLIP
        ↓
Positive CLIP Text Encode.clip
        ↓
KSampler.positive

Load Checkpoint.CLIP
        ↓
Negative CLIP Text Encode.clip
        ↓
KSampler.negative

Empty Latent Image
        ↓
KSampler.latent_image

KSampler
        ↓
VAE Decode.samples

Load Checkpoint.VAE
        ↓
VAE Decode.vae

VAE Decode
        ↓
Save Image.images

```

# 24. Load Checkpoint 的 CLIP 应该连接哪里？

这是第一次搭建工作流时容易弄错的地方。

`Load Checkpoint` 输出：

```text
MODEL
CLIP
VAE

```

其中：

```text
CLIP

```

不能直接连接 KSampler。

正确方式：

```text
Load Checkpoint.CLIP
        ↓
CLIP Text Encode.clip

```

然后：

```text
CLIP Text Encode
        ↓
CONDITIONING
        ↓
KSampler

```

也就是说：

```text
CLIP
 ↓
CLIP Text Encode
 ↓
CONDITIONING
 ↓
KSampler

```

----------

# 25. 模型、参数一致时结果是否一致？

本次使用的模型：

```text
stable-diffusion-xl-base-1.0

```

在相同环境和相同参数下进行测试。

如果以下条件都一致：

```text
模型
Prompt
Negative Prompt
Seed
Steps
CFG
Sampler
Scheduler
分辨率

```

那么生成结果应该具有很高的一致性。

因此做算法测试时，可以把 Seed 固定下来。

----------

# 26. 推荐的参数测试方法

不要同时修改很多参数。

例如第一组：

```text
Sampler: euler
Scheduler: normal
Steps: 20
CFG: 7
Seed: 123456789

```

然后只修改：

```text
Sampler

```

比较：

```text
euler
euler_ancestral
dpmpp_2m
dpmpp_2m_sde

```

之后固定 Sampler，再测试 Scheduler：

```text
normal
karras
exponential
simple

```

这样才能知道到底是哪一个参数造成了图像变化。

# 29. 最终工作流

以后重新搭建 SDXL 工作流时，可以直接按照下面的结构：

```text
Load Checkpoint
       │
       ├──────── MODEL ──────────→ KSampler
       │
       ├──────── CLIP
       │             │
       │             ├→ Positive CLIP Text Encode
       │             │          │
       │             │          ↓
       │             │      KSampler.positive
       │             │
       │             └→ Negative CLIP Text Encode
       │                        │
       │                        ↓
       │                    KSampler.negative
       │
       └──────── VAE ────────────→ VAE Decode


Empty Latent Image ─────────────→ KSampler.latent_image

KSampler ───────────────────────→ VAE Decode

VAE Decode ─────────────────────→ Save Image

```

这就是最基础、最重要的一套 **ComfyUI + Stable Diffusion XL 图像生成工作流**。
